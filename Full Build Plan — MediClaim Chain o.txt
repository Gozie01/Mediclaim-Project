8 Gaps → What We Build to Close Each
#	Gap	Solution We Build
1	Gas costs unvalidated	Automated gas benchmark script; table of deploy + per-claim costs on PureChain
2	No production-scale test	load_test.js — 1,000 claims in parallel, measure TPS + latency
3	ZK-proof not applied to claims	circom circuit for consent; ZKConsentVerifier.sol in PatientProfile
4	GDPR/HIPAA erasure conflict	revokeAndErase() function — deletes IPFS pin, writes tombstone hash on-chain
5	Oracle trust / single point of failure	MultiOracleConsensus.sol — 3 independent Node.js oracle nodes, 2-of-3 majority
6	Cross-chain interoperability	FHIR R4 Patient/Claim resource schema in all contract data fields
7	No AI/ML fraud detection	fraudFlag field in MediClaim.sol writable by oracle; off-chain ML model (isolation forest) posts anomaly scores
8	Non-standard identity/consent	FHIR-aligned PatientProfile with DID (Decentralized Identifier) support
Five Test Scenarios for Professor Demo
Happy Path — Patient consents → Hospital submits claim → Oracle validates codes → Auto-approved + paid in seconds
Fraud Detection — Hospital submits claim with invalid ICD code → Oracle rejects → Claim denied, fraud event emitted
Policy Expired — Patient's policy lapsed → InsurancePolicy.isActive() returns false → Claim auto-rejected
GDPR Erasure — Patient invokes right-to-erasure → IPFS record deleted, on-chain tombstone written, audit trail preserved
Oracle Disagreement — 1 of 3 oracle nodes submits wrong result → 2-of-3 consensus overrides → correct outcome, bad node flagged
Mobile App — 3 Role Screens
Role	Key Actions
Patient	Register identity, upload medical history to IPFS, grant/revoke consent, track claim status in real time
Hospital	Submit claim with IPFS treatment hash, view claim status, receive payment notification
Insurer	Register policies, view active claims, see oracle validation results, flag fraud
